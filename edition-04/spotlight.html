⚡ feature #12315 WhatsApp Email comunicacao-produtores.module.ts
Comunicação com Produtores — email + WhatsApp em um único módulo
❌ problema
A comunicação com o produtor estava espalhada entre lembretes do formulário, notificações pontuais e mensagens manuais. Faltava um hub onde o operador pudesse selecionar produtores, escolher canal (email/WhatsApp), usar templates com variáveis e acompanhar status de entrega por contato — tudo no mesmo lugar.
✓ o que entregamos
→ Módulo backend com templates + destinatários + entregas
→ Tela em Operações: listagem com filtros (título/canal/período) + tabs por produtor
→ Templates Email/WhatsApp com variáveis substituídas no envio
→ Webhooks centralizados: Evolution + Resend com provider_message_id
→ Múltiplos contatos por produtor: 1 entrega/contato + snapshot + status consolidado por canal
→ Permissões de endpoint + integração com picklist de produtores
🎯 destaque técnico
Webhooks roteados em um só lugar: independente do canal (Evolution para WhatsApp, Resend para email), o status da entrega volta pro mesmo handler. O provider_message_id amarra a entrega ao registro de comunicação — mesmo com N contatos por produtor, o status consolidado fica coerente.

📊 feature #12342 #12361 #12387 #12337 sicar-dashboard.service.ts
Painel de Análise Socioambiental — o mundo externo dentro da propriedade
❌ problema
A análise da propriedade dependia de cruzar informações de várias bases oficiais (PRODES, IBAMA, Lista Suja do MTE) com a base de fazendas — e isso era manual ou simplesmente não existia. Era preciso trazer essas bases para dentro do Agrotrace de forma automática, rastreável (com data de cada consulta) e auditável (com relatório formal).
✓ o que entregamos
→ #12193 Integração base PRODES via RuralShape — tracking Sicar/Prodes/Ibama/Deter na PropriedadeCar
→ #12239 CAR Estadual + resolução CAR federal via RuralShape
→ #12301 Investigação manual + status de camadas (fresh/warning/stale/empty)
→ #12342 Importação Lista Suja do MTE (trabalho análogo a escravo) com polling automático
→ #12361/#12332 Recortes temporais PRODES — RTRS 2016-2019, pós-2008, ordenação
→ #12362 Card de resumo MTE no dashboard de análise
→ #12337 Filtros do painel + zoom com scroll + endpoints summary/overview
→ #12387 Relatório PDF "Análise Socioambiental" com verificador de documento
🎯 destaque técnico
Refactor de payload monolítico em summary e overview separados (#12337) — o dashboard inicial carrega só o resumo, e os detalhes vêm sob demanda. Performance subiu e os componentes ficaram reusáveis. Stack: SicarDataProcessorService + SicarDashboardService + procedure consolidadora.

⚡ Lightning #12348 Sentinel-2 NDVI sicar-inspecao-vegetacao.service.ts
Inspeção de vegetação em APP via NDVI Sentinel-2
o que entregamos
→ SicarInspecaoVegetacaoService — orquestração da análise (selecionar cena, processar, gerar preview)
→ SentinelStacClient — busca cenas Sentinel-2 L2A no STAC
→ Cálculo de estatísticas NDVI sobre a geometria da APP
→ Preview PNG gerado server-side + cache via anexo da propriedade
→ html2canvas para relatórios contextuais com mapa + dados
→ Endpoints: solicitação, listagem, processamento, preview, histórico
→ SicarDataProcessorService — integridade de referências (temas/status/tipos)
por que importa
Quando uma propriedade declara APP preservada, agora dá pra auditar isso direto do satélite, sem ter ido no campo. O NDVI das cenas Sentinel-2 mostra cobertura vegetal na própria geometria da APP — e o histórico fica anexado à propriedade pra consulta futura.

// 1. busca cenas Sentinel-2 L2A
// 2. recorta sobre a geometria da APP
// 3. calcula NDVI = (NIR - RED) / (NIR + RED)
// 4. gera PNG + estatísticas

async inspect(carId: number) {
  const geom = await this.loadAppGeometry(carId)
  const scenes = await stac.searchL2A(geom)
  const stats = await this.computeNDVI(scenes, geom)
  const png = await this.renderPreview(stats)
  await this.cacheAsAttachment(carId, png)
  return { stats, png }
}

🤖 feature ATER Digital WhatsApp ater-whatsapp.config.ts
ATER Digital — WhatsApp + n8n com infra própria
❌ problema
O produtor está no WhatsApp — não no app. Precisávamos de um canal de IA que reconhecesse o produtor, consultasse dados reais da fazenda no RuralShape, agendasse visita técnica e disparasse alertas — sem acoplar o Typebot ao núcleo da API. A complexidade pediu uma orquestração externa e infra dedicada.
✓ o que entregamos
→ Migração Typebot → n8n como orquestrador (renomeação completa da ponte)
→ Infra na VPS: typebot_db isolado, proxy Caddy via Cloudflare Tunnel, SMTP Gmail
→ Onboarding WhatsApp: ponte web, validação de tokens, perfil do produtor
→ Agendamento de visita técnica: slots, Google Meet, calendário
→ Alertas WhatsApp com opt-in + armazenamento de entregas
→ RuralShape pelo bot: cliente + normalizador + status de risco
→ n8n → WhatsApp: adaptação das respostas para formatação correta
🎯 destaque técnico
Saímos de uma integração acoplada para uma arquitetura desacoplada: Evolution recebe → n8n orquestra → API expõe contexto. Toda lógica de conversa fica no n8n; a API só serve dados. Pareamos com Elias para construir os fluxos.
