spotlights / thielson / clonar-diagnostico.sql · 2 min
#12934 · BACKEND

Clonar diagnóstico
sem reconstruir respostas.

O cenário aqui é simples de explicar: existe um diagnóstico pronto e ele precisa ser reaproveitado para outro produtor, mantendo protocolo, safra, origem, destino e respostas no contexto certo.

Origem

Diagnóstico concluído fornece protocolo, safra e conjunto de respostas a replicar.

Destino

Produtor e propriedade de destino recebem a estrutura clonada no contexto correto.

Contrato

A função explicita os dados obrigatórios antes de iniciar a cópia.

Reuso

O fluxo evita recriar manualmente diagnósticos semelhantes entre produtores.

Resultado: a clonagem passa a ser uma operação controlada de backend, não uma sequência manual de preenchimento.
const copia = clonarDiagnostico({ protocolo, safra, origem: propriedadeA, destino: propriedadeB, }); -- recorte isolado: -- clonar diagnostico produtor -> produtor.

lightning / monorepo-structure.md · 4 min
LIGHTNING · AGROTRACE

Monorepo sem pacote acoplado.

O Agrotrace saiu de um único package.json compartilhado e passou a organizar cada aplicação e biblioteca com seu próprio pacote.

📦 Pacotes independentes

Cada app e lib evolui com versionamento e dependências próprios, sem travar atualizações cruzadas.

🧭 Workspace explícito

pnpm-workspace controla quais pacotes entram no monorepo e como eles são instalados.

🐳 Imagens menores

O Docker instala somente os pacotes usados por aquela aplicação, reduzindo dependências carregadas.

🚀 Mais autonomia

Um app pode atualizar sua lib sem obrigar todas as outras aplicações a acompanhar a mesma versão.

Resultado: menos acoplamento na manutenção, builds mais focados e espaço para cada aplicação evoluir no próprio ritmo.
packages: - apps/* - libs/* # cada app instala o que usa pnpm --filter agrotrace-web install pnpm --filter agrotrace-api install // antes: uma versão para todos // agora: dependências por aplicação
